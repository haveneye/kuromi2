# 우리 집 강아지

## 현재 적용: 로컬 돌봄 규칙 v2 (2026-10-31)

HTML/CSS/JavaScript로 구성된 강아지 게임입니다. 지갑은 Google 로그인 뒤 기존 가족 학습 앱 Firebase 프로젝트 `kuromi-app`의 `마리` 프로필 `points`를 읽습니다. 구매 요청은 `functions/`의 서버 callable이 카탈로그 가격을 확인하고 잔액 차감·영수증·장난감 소유권을 Firestore transaction으로 기록하도록 구성했습니다. 구매 callable은 Firebase Console의 `artifacts/kuromi-app-default/public/data/config/puppyGameAccess` 문서에 `ownerUid`가 설정되고 Cloud Functions가 배포된 뒤에만 구매를 처리합니다. 돌봄·훈련 상태는 현재 브라우저 저장소를 사용합니다.

### 수치와 시간

수치·훈련 설정은 care-rules.js의 SETTINGS/TRICKS, 계산은 calculate/applyEffect에 모았습니다. 친밀도·포만감은 0~100입니다. 새 입양은 10/70, 습득 0개·숙련도 0%, 최초 상태는 낯가림입니다. 기존 사용자는 최초 v2 실행 당시의 v1 계산 수치를 기준값으로 고정하고 이후부터 새 규칙을 적용합니다. 이름·성별·성장 단계·기존 식사/간식/장난감 원본 기록을 삭제하지 않으며 과거 보상을 새 수치로 다시 지급하지 않습니다.

| 행동 | 친밀도 | 포만감 |
| --- | --- | --- |
| 식사 | +1 | +30 |
| 끼니 누락 | -6 | -15 |
| 간식 실제 급여 | +4 | +5 |
| 산책 완료 | +3 | -10 |
| 장난감 놀이 완료 | +1 | -5 |
| 훈련 성공 | +1 | -3 |
| 훈련 실패 | 0 | -3 |
| 시간 1시간 | 0 | -2 |
| 매일 자정 기본 감소 | -3 | 0 |
| 그날 산책 미실시, 다음 자정 | -2 | 0 |

아침 07~10, 점심 12~15, 저녁 17~20이며 종료 시각은 제외합니다. 식사 및 일일 제한은 Asia/Seoul 기준입니다. 입양 전 끝난 끼니는 벌점을 부과하지 않습니다. 산책은 다녀온 뒤 완료 버튼으로 기록하는 게임 내 활동이며 GPS 추적 기능은 없습니다. 산책 보상은 하루 1회입니다. 장난감 놀이 하루 3회 및 친밀도 +10 한도과 수면 시간 22~06시는 유지합니다. 한도 도달 후 놀이 보상은 0이며 포만감 비용은 계속 적용합니다.

시간 감소는 입양/이관 시각부터 완료된 1시간마다 -2입니다. 포만감 21~69에서는 연속 3시간마다 친밀도 -2, 0~20에서는 -3입니다. 구간 변경 시 그 시점부터 타이머를 새로 계산하고 70 이상이 되면 중지합니다. 두 구간을 동시에 적용하지 않습니다. 앱 종료 중 경과도 저장된 시작점과 행동 기록으로 재계산하며 조회 횟수에 따라 감소가 중복되지 않습니다. 자정에 기본 감소와 전날 산책 미실시 감소를 각각 한 번 반영합니다.

### 간식·훈련·화면

간식은 상점에서 테스트 구매하고 인벤토리의 보유 간식에서 급여할 수 있습니다. 종류와 관계없이 한국 날짜 하루 3개이며 구매만으로는 수치가 오르지 않습니다. 가격/보유 수량은 기존 데이터를 유지합니다. 친밀도별 모습과 훈련 도감 그림은 첨부 원본 assets/bond-training-reference.png를 SVG 표시 영역으로 보여주며 원본을 재생성하지 않았습니다. 식사 누락 그림, 먹기/간식 장면 4초, 수면 그림의 우선순위를 유지합니다. 포만감 게이지와 작은 훈련 요약을 추가했고 상세 훈련은 하단 훈련 버튼에서 엽니다.

훈련 순서: 앉아(30) → 손(50) → 엎드려(70) → 빙글빙글(80) → 하이파이브(90). 이전 기술 숙련도 100%와 현재 친밀도가 모두 필요합니다. 성공 확률 기본 80%, 성공 시 정수 10~20% 상승이며 SETTINGS에서 조정합니다. 실패도 하루 횟수와 포만감 비용을 사용합니다. 전체 기술 합산 하루 3회, 한국 자정 초기화이며 습득 기술은 친밀도 하락 후에도 유지됩니다. 현재 횟수·기술·숙련도·다음 조건과 성공/실패 결과를 표시합니다.

### 저장과 안전 범위

v1 localStorage 원본 키와 별도로 our-puppy:v2:care에 이관 기준, :activities에 훈련/산책 원자적 기록, :checkpoint에 마지막 계산 시각·수치·저포만 구간 시작 시각을 저장합니다. 체크포인트 갱신이 행동 기록을 덮어쓰지 않게 분리했습니다. 기존 Web Lock our-puppy-care에서 변경 직전 데이터를 다시 읽고 검증하며 요청 ID 중복을 거절합니다. 한 브라우저의 여러 탭에 대한 보호이며 여러 기기의 거래를 보장하는 서버 기능은 아닙니다. 저장이 손상되면 덮어쓰지 않고 중단합니다.

전체 테스트 초기화는 강아지 이름·성별만 보존하고 새 입양 상태(친밀도 10, 포만도 70, 아기 성장 단계, 개인기 0%)로 되돌립니다. 모든 날짜의 식사·간식·훈련·산책·놀이 기록과 보유 간식·장난감도 비우며, 간식 및 장난감 테스트 잔액은 각각 1,000으로 설정합니다.

## 실행

`index.html`을 브라우저에서 엽니다. 이름과 성별을 정하면 메인 화면으로 이동하고 이 브라우저에 저장됩니다.
저장된 강아지가 있으면 다시 열 때 메인 화면을 보여줍니다.
첫 화면의 미리보기는 저장된 강아지가 없을 때 식사 보상을 지급하지 않습니다.
이미 열어 둔 파일은 새로고침해야 변경이 반영됩니다.

## 화면과 캐릭터

사용자가 확정한 방 배경, 카드 색상, 글꼴, 2D 그레이트데인 그림을 유지합니다.
몸통은 고정하고 SVG 표시 영역으로 분리한 꼬리만 흔듭니다.
동작 줄이기 설정을 사용하면 꼬리 모션을 끕니다.
친밀도, 포만도, 오늘의 식사 세 카드는 실제 로컬 상태를 표시합니다.
학습캐시는 Google 로그인 후 마리 프로필의 기존 Firestore `points`를 실시간 표시합니다. 미연결 상태는 별도 테스트 지갑으로 표시되며 학습 앱 잔액을 변경하지 않습니다. 전체 테스트 초기화는 로컬 돌봄·테스트 지갑만 초기화합니다. Firebase 기본 Firestore 규칙은 기존 설정을 변경하지 않았습니다. 구매 보안은 서버 callable에서 소유자 UID, 서버 카탈로그 가격, 중복 요청, 잔액을 검증합니다.

증가·감소량은 이전 숫자 로직이 없어 이번에 정한 값이며 `game-state.js`의 `RULES`에서 조정합니다.

## 저장과 중복 방지

서버 저장 방식이 없어 `localStorage`를 사용합니다. 같은 기기·브라우저·저장 영역에서 유지됩니다.
다른 기기나 브라우저와 동기화하지 않으며, 사용자가 브라우저 데이터를 지우면 기록도 사라집니다.

강아지 정보와 초기 수치는 `our-puppy:v1:profile`에,
식사 기록은 `our-puppy:v1:main:현지날짜:식사종류:completed` 키에 보관합니다.
놓친 식사는 같은 식별자의 `missed` 키에 보관하며 완료 기록을 우선합니다.
이전 날짜의 키를 삭제하지 않고 내부 이력에 포함합니다.

식사 완료와 보상을 단일 기록으로 저장하고 수치는 기록에서 계산합니다.
같은 날짜·식사 키를 여러 번 읽거나 같은 키에 쓰더라도 보상을 중복 합산하지 않습니다.
지원 브라우저에서는 Web Locks로 여러 탭의 식사 처리를 직렬화하고,
그 외 환경에서도 날짜·식사별 단일 키를 기준으로 보상을 한 번 계산합니다.
저장 공간 접근 또는 저장에 실패하면 오류를 표시하고 먹이기를 중단합니다.
식사 가능 여부는 잠금을 얻은 뒤의 현재 시간으로 다시 판정합니다.
기기 시계 표시와 식사 판정 함수는 분리되어 있습니다.

Node.js가 설치된 환경에서 실행합니다. 패키지 설치는 필요 없습니다.

```powershell
node --test tests/game-state.test.cjs tests/app.test.cjs tests/snacks.test.cjs
```

## 간식

메인 화면의 간식·상점·인벤토리 버튼으로 각 용도의 창을 엽니다. 창 안의 상단 탭 메뉴는 없습니다.
상점에는 간식 상품과 구매 버튼을 표시하고, 인벤토리는 보유 수량이 있는 간식의 이름과 수량만 표시합니다.
간식은 보유 0개부터 시작합니다. 학습캐시가 연결되면 마리 프로필의 기존 포인트로 구매하고, 연결 전 미리보기에서는 테스트 캐시를 사용합니다.
종류와 관계없이 기기 현지 날짜 기준 하루 합계 3개까지만 급여할 수 있습니다.
구매 횟수에는 일일 제한이 없으며 테스트 잔액 범위에서 구매합니다.

| 종류 | 가격 | 친밀도 | 포만도 |
| --- | ---: | ---: | ---: |
| 우유껌 | 30 | +2 | +5 |
| 강아지 쿠키 | 50 | +4 | +10 |
| 고기 간식 | 100 | +9 | +20 |

구매만으로 급여 횟수나 돌봄 수치가 변하지 않습니다. 실제 급여 시 보유 수량 1개와 하루 횟수 1회를 반영하고 보상을 적용합니다.
3회를 다 쓰면 모든 급여 버튼을 끄고 ‘오늘 간식은 다 먹었어요! 내일 다시 주세요 🐶’를 표시합니다.
급여 성공 시 기존 올블랙 기쁨 그림과 ‘마리야 간식 고마워! 🥰’를 4초간 보여준 뒤 원래 모습으로 복귀합니다.

구매·급여 내역은 `our-puppy:v1:snacks`에 거래 ID와 현지 날짜를 포함한 단일 거래 목록으로 저장합니다.
재고·테스트 잔액·하루 횟수·보상을 같은 거래에서 계산해 부분 차감과 중복 보상을 방지합니다.
브라우저 Web Locks의 기존 `our-puppy-care` 잠금으로 여러 탭의 거래를 직렬화합니다.
안전한 잠금을 지원하지 않는 브라우저에서는 간식 거래를 비활성화하고 안내합니다.
날짜 변경 시 오늘 횟수만 0으로 표시하고 재고·구매 내역·지난 급여 기록을 보존합니다.
전체 테스트 초기화는 로컬 게임 진행 상태와 테스트 지갑만 초기화하고, 실제 학습 앱 잔액은 변경하지 않습니다.

지갑 연결 후 간식 구매는 기존 `artifacts/kuromi-app-default/public/data/profiles/마리` 문서의 `points`를 차감합니다. 각 구매는 Firestore transaction과 중복 방지 영수증으로 기록하고, 영수증은 연결한 게임의 간식·장난감 보유 내역 복구에 사용합니다. 캐시 잔액은 실시간으로 표시합니다.
추가 파일 `tests/snacks.test.cjs`에서 급여 상한·동시 요청·원자적 저장·복원·자정 전환을 검증합니다.
참고 이미지 원본은 `assets/snack-reference.png`에 보관합니다.

## 업로드한 블랙 그레이트데인 디자인

`design/black-great-dane.png` 원본의 아기 단계, 밥 먹기, 간식 장면을 화면에서 각각 잘라 표시합니다. 시작 화면과 프로필에도 같은 아기 강아지를 사용합니다. 식사와 간식 급여 성공 시 해당 장면을 4초간 표시하고 기본 모습으로 돌아옵니다. 이미지 로딩 실패 시 기본 모습을 유지합니다. 원본 파일의 배경은 그대로 표시합니다.

## 장난감 상점과 놀이

장난감 구매는 callable 서버 함수를 통해 같은 학습캐시 지갑에서 처리하며, 구매 영수증은 Firebase에 기록해 이 게임의 보유 내역을 복원합니다. 놀이 횟수·보상 및 나머지 돌봄 상태는 이 브라우저의 localStorage에 보관합니다.

학습 앱 미연결 미리보기에서는 장난감 테스트 캐시가 5,000P로 시작하며, 전체 테스트 초기화 뒤에는 1,000P입니다. 연결된 구매는 마리 프로필의 같은 학습캐시 잔액을 사용합니다.

상점 → 장난감 상점에서 10종을 구매합니다. 인벤토리 → 보유 장난감에서 소유 내역을 확인하고, 놀기 메뉴에서 보유 장난감을 선택합니다. 첨부 원본은 `assets/toy-shop-reference.png`에 보관하고 화면에서는 필요한 그림 부분만 표시합니다. 강아지는 기존 투명 배경 블랙 그레이트데인 이미지를 유지하며 장난감마다 다른 움직임·대사와 장난감 그림을 표시합니다.

보유 장난감을 골라 2초 놀이 후 구매 가격에 따라 친밀도와 포만감을 반영하고, 강아지 장면은 총 4초 뒤 친밀도 이미지로 돌아갑니다. 하루 3회, 장난감 놀이 친밀도 합계 +10까지입니다. 포만도가 20 이하이면 놀이할 수 없습니다. 친밀도 100에서 넘치는 보상은 버리며 포만도는 표 수치만큼 낮아지고 0 아래로 내려가지 않습니다. 한국 시간 자정에 횟수와 친밀도 한도가 초기화됩니다. 06:00 포함~22:00 제외에 놀이할 수 있으며 수면 중 구매는 가능합니다.

구매 차감과 소유권을 단일 로컬 저장으로 처리하고, 놀이 횟수·친밀도·포만감·보상도 단일 로컬 기록으로 저장합니다. 기존 `our-puppy-care` Web Lock으로 여러 탭의 식사·간식·장난감 거래를 함께 직렬화하며 요청 ID 재사용 시 중복 보상을 거절합니다. Web Locks 미지원 시 장난감 거래를 비활성화합니다. 놀이 도중 새로고침하면 완료되지 않은 놀이 보상은 지급하지 않습니다.

검증 명령: `node --test tests/game-state.test.cjs tests/app.test.cjs tests/snacks.test.cjs tests/toys.test.cjs`

수면 그림: 22:00~다음 날 06:00에는 원본 design/black-great-dane.png의 잠자기 장면을 표시합니다. 아침 06:00에 기본 그림으로 돌아오며, 식사·간식 장면이 종료된 뒤에도 현재 시각에 맞는 그림으로 복귀합니다.

수면 중 하단 메뉴: 22:00~06:00에는 밥 주기·간식·놀기·산책·훈련을 비활성화하고 회색으로 표시합니다. 상점·인벤토리는 계속 이용할 수 있으며 06:00에 돌보기 메뉴가 자동 복원됩니다. 미리보기에서도 동일하게 적용합니다.

끼니를 놓친 뒤의 메인 그림: 첨부 원본은 assets/puppy-waiting-for-food.png에 복사하여 편집 없이 표시합니다. 실제 놓친 식사 기록 이후 밥·간식 급여 성공 기록이 없으면 슬픈 모습이 유지되며, 구매나 놀이로는 해제되지 않습니다. 급여 성공 시 기존 먹기 장면을 4초 표시한 뒤 기본 모습으로 돌아옵니다. 이후 다시 끼니를 놓치면 슬픈 모습으로 바뀝니다. 기존 저장 기록에서 상태를 계산하므로 새로고침·날짜 변경에도 유지됩니다. 수면 시간은 기존 잠자는 그림을 우선하고, 이미지 로딩 실패 시 기본 캐릭터를 유지합니다. 입양 이전의 식사는 이 상태를 유발하지 않습니다.

이름 복원: 시작 폼이 주소의 name·gender 값으로 제출된 경우 유효한 값을 기존 강아지 프로필에 저장하고 주소에서 해당 매개변수를 제거합니다. 기존 성장·식사·간식 내역은 유지합니다. 이후에는 저장된 프로필을 사용하며, 이름 변경 시에도 이전 주소 값이 남지 않도록 정리합니다.
